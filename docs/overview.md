# 개요 & 전체 플로우

VibeCheck은 **사람이 Claude Code CLI로 직접 바이브 코딩할 때 얼마나 효율적으로 만드는지** 정량 측정하는 프로그램이다. 고정된 문제 세트에서 과제를 골라 대시보드에서 시작하면, 사람이 VS Code + 대화형 Claude Code CLI로 직접 풀고, 소요 시간·토큰 사용량·결과물 품질(테스트 통과율 + LLM 채점)을 자동으로 측정해 웹 대시보드에 기록/비교한다.

> 초기 버전은 정반대 방향("AI가 헤드리스로 혼자 푼다")이었다가 방향을 바꿨다. 그 시절 메커니즘(`src/lib/runner.ts`, [cli-spec.md](./cli-spec.md))은 코드/문서에 참고용으로 남아있지만 지금 대시보드는 안 쓴다 — 지금 실제로 쓰는 건 [manual-mode.md](./manual-mode.md)다.

## 목적

- 사람이 다양한 난이도의 코딩 과제를 Claude Code CLI를 도구로 써서 얼마나 빠르고, 얼마나 적은 토큰으로, 얼마나 정확하게 완료하는지 정량적으로 측정한다.
- 실행 → 측정 → 채점 → 기록을 최대한 자동화해서, 사람은 코딩에만 집중하고 나머지는 시스템이 재게 한다.
- (향후) 사람/설정을 바꿔가며 같은 문제 세트로 비교할 수 있는 기반을 만든다.

## 전체 플로우

1. **문제 선택** — `problems/*.json` 고정 문제 세트에서 대시보드로 직접 고른다(랜덤 선택 없음 — 문제 하나하나가 "문서/스킬/hook 같은 하네스 엔지니어링을 실제로 활용했는가"를 가르도록 공들여 설계돼 있어서, 사람이 뭘 풀지 스스로 정하게 한다). 포맷(문제별 `maxTokens`/`maxDurationMs` 포함)은 [problem-set.md](./problem-set.md) 참고.
2. **워크스페이스 생성 + VS Code 오픈** — 문제별 starter 파일(있다면)을 격리된 워크스페이스(프로젝트 밖, `RUN_WORKSPACES_DIR`)로 복사하고 VS Code를 그 폴더로 연다. 실행마다 새 디렉터리를 써서 문제 원본과 이전 실행 결과가 섞이지 않게 한다.
3. **대화형 세션 실행 + 실시간 한도 집행** — 워크스페이스에 심어둔 VS Code 자동 태스크로 통합 터미널에서 빈 대화형 `claude` 세션을 띄운다(프롬프트 자동 제출 안 함 — 사람이 화면에 표시된 문제를 보고 직접 타이핑해야 한다). 벽시계 시간과 세션 트랜스크립트 기반 토큰 추정치를 실시간으로 폴링해서, 문제의 `maxTokens`/`maxDurationMs`를 넘는 순간 그 프로세스만 정확히 찾아 강제 종료하고 "실격"으로 표시한다. 메커니즘/실측으로 발견한 함정은 [manual-mode.md](./manual-mode.md) 참고.
4. **(단계형 문제라면) 단계별 제출/게이트** — 대시보드의 "이 단계 제출" 버튼을 누르면 현재 단계의 게이트 테스트만 채점해서 통과 여부를 알려준다. 통과해야만 다음 단계의 데이터/문서가 워크스페이스에 풀리고 다음 요구사항이 화면에 공개된다 — 전체 스펙을 한 번에 다 보여주고 시작하면 "문서 한 번 스스로 찾아 읽고 한 방에 끝내기"가 가능해져서 측정 목적이 무의미해지므로, 실제로 단계를 밟아나가야만 진행되게 만든 것이다. 상세는 [problem-set.md](./problem-set.md) 참고.
5. **완료 처리** — 사람이 "완료" 버튼을 누르면(또는 실격/세션 자연종료를 대시보드가 감지하면 자동으로) 그 시점까지의 추정치를 확정(freeze)한다.
6. **평가** — "완료" 상태인 run만 자동 테스트 통과율 + LLM 채점(OpenAI)을 수행한다. 실격 run은 평가를 생략한다. 단계형 문제는 이 시점에 워크스페이스가 전체 히든 테스트로 덮어써져서, 나중 단계를 안 풀고 일찍 끝내도 완전한 스펙 기준으로 채점된다. 상세는 [evaluation.md](./evaluation.md) 참고.
7. **저장** — 실행 결과(상태: 완료/실격, 시간, 토큰 추정치, 테스트 결과, LLM 채점)를 DB에 기록.
8. **대시보드 표시** — 실행 이력, 개별 실행 상세(코드 diff 포함)를 웹에서 조회. 실격 run은 완료 run과 구분해서 보여주고, 토큰/시간 수치는 "하네스 추정치"임을 밝힌다.

아키텍처/디렉터리 구조는 [architecture.md](./architecture.md) 참고.
