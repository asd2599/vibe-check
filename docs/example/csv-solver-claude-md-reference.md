# 레퍼런스 — csv-summarizer-staged 솔버용 워크스페이스 CLAUDE.md

> 이건 **솔버(응시자)가 워크스페이스 루트에 직접 쓰는 `CLAUDE.md`의 모범 예시**다. "CLAUDE.md를
> 지속 메모리로 쓰고 단계 사이 `/clear`로 휘발성 컨텍스트를 날린다"는 하네스 기법을 이 문제에
> 적용한 것. 아래 코드블록 내용을 워크스페이스의 `CLAUDE.md`로 저장해서 쓴다.
>
> ⚠️ **문제 스타터에 넣지 마라.** 스타터에 넣으면 세션 시작 시 자동 로드돼서 정답을 흘리고, "응시자가
> 직접 하네스를 구성했는가"라는 측정 대상 자체가 사라진다. 이 파일은 **저자가 기법을 이해하기 위한
> 참고용**일 뿐이다.
>
> 실제로는 처음부터 완성본을 쓰는 게 아니라, **단계가 풀릴 때마다 한 줄씩 append** 하며 자란다
> (아래 `[2]/[3]/[4]` 표시가 각 단계에서 추가되는 부분).

## 저장할 CLAUDE.md 내용

```markdown
# summarize.js 작업 메모

목적: `node summarize.js <파일경로>` → stdout에 JSON 한 줄.

## 고정 규칙 (놓치면 히든 테스트 실패)
- 출력 필드명은 정확히 `{ "total", "counted", "skipped" }` — sum/count/rows 아님.
- `amount` 컬럼은 헤더 "이름"으로 찾는다. 인덱스 하드코딩 금지 (파일마다 컬럼 순서가 다름).
- 헤더 행은 counted/skipped 어디에도 세지 않는다.

## 구조 (이 분리를 유지 — 단계마다 함수 "하나"만 수정하면 되게)
- `parseLine(line, delim)`  : 한 줄 → 필드 배열. 따옴표(RFC 4180) 처리를 여기서 담당.
- `parseAmount(raw)`        : 문자열 → number | null(무효). 유효성 판정을 여기서 담당.
- 합산 루프                 : 유효값만 누적, counted/skipped 집계.

## 단계별 규칙 (풀리면 추가)
- [2] 구분자는 확장자로 판단: `.csv`=`,`  `.tsv`=`\t`  `.psv`=`|`.  → parseLine에 delim 인자.
- [3] 따옴표로 감싼 필드 안엔 구분자·개행이 들어갈 수 있음. `""`는 escape된 따옴표.
      순진한 split 금지 → parseLine을 문자 상태머신으로.
- [4] 유효 금액 = `/^-?(\d{1,3}(,\d{3})*|\d+)(\.\d+)?$/` , 쉼표 제거 후 `Number()`.
      · `"1,200"`→1200(유효),  `₩1,200`/`$50`/`N/A`/`-`/빈칸→skip,  `-500`→포함.
      · 반올림에 `toFixed(2)` 쓰지 말 것 (934.005 → "934.00"으로 틀림).
        정수단위 합산 후 half-up:
          `milli += Math.round(n * 1000)`
          `total = Math.floor((milli + 5) / 10) / 100`

## 작업 규율 (토큰 예산 방어)
- 단계 사이에 `/clear` — 이 파일은 자동으로 다시 로드되니 핵심 규칙/구조는 유지된다.
- 방금 쓴 summarize.js를 "확인용"으로 다시 Read 하지 않는다.
- `npm test`는 글자 하나 고칠 때마다 돌리지 않는다 — 모아서 한 번.
```

## 왜 이렇게 짰나 (설계 의도)

- **짧게 유지한다.** CLAUDE.md는 매 턴 컨텍스트에 다시 들어가므로, 길면 오히려 턴당 비용이 는다.
  "코드를 보면 알 수 있는 것"은 빼고, **잊기 쉽거나 관습과 다른 함정값·구조 결정**만 담았다.
- **구조를 먼저 못 박는다.** `parseLine/parseAmount/합산` 분리를 메모에 고정해두면, `/clear` 후에도
  Claude가 "이 파일은 세 함수로 나뉘어 있고 3단계는 parseLine만, 4단계는 parseAmount만 고치면 된다"를
  기억한다 → 전면 재작성(가장 큰 토큰 낭비)을 원천 차단.
- **`/clear`와 짝이다.** 이 파일이 durable 메모리 역할을 하기 때문에, 단계 사이 휘발성 컨텍스트
  (테스트 출력·디버깅 왕복)를 과감히 날려도 핵심을 안 잃는다. 이게 4단계에서 컨텍스트가 부풀어
  예산이 터지던 문제를 막는 핵심.
- **4단계 함정을 미리 못 박는다.** `toFixed` 버그와 쉼표 vs 통화기호 판정을 메모에 박아두면,
  4단계에서 원인 모른 채 값만 바꿔가며 재시도(가장 비싼 후반 턴에서의 thrash)를 안 하게 된다.
