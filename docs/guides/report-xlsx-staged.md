# report-xlsx-staged 공략집

> ⚠️ **스포일러.** 정답과 히든 테스트 기대값이 그대로 있다. 참가자에게 보이지 마라 — [README](./README.md) 참고.

## 한눈에

| | |
|---|---|
| **측정 대상** | 참가자가 **스스로** 공식 스킬 생태계(`anthropics/skills`의 `xlsx`)를 떠올려 찾아 쓰는가 — 우리는 힌트를 일절 안 준다 |
| 난이도 / 분류 | medium / report |
| 산출물 | `output/report.xlsx` (생성 스크립트는 도구·언어 무관) |
| 예산 | `maxCostUsd` $2.5 · 기준선 1,200,000 가중 토큰 |
| 시간 | 적정 10분 → 하드컷 15분 |
| 실측 완료 시간 | 6.8, 8.3분 (2건) |

**A/B를 config로 강제하지 않는다.** 문제 파일은 하나뿐이고, 스킬을 쓴 run과 안 쓴 run은 나중에
트랜스크립트/워크스페이스 diff로 **사후 분류**해서 비교한다.

> 스킬 사용 흔적을 찾는 법: 워크스페이스에 `.claude/skills/xlsx/`와 `skills-lock.json`이 생긴다.

## 변별축은 문서 독해가 아니라 **라이브러리 정확성**이다

xlsx를 고른 이유는 결과 파일을 다시 열어 셀 값·타입·수식·서식·병합·틀고정을 스크립트로 결정론적으로
검사할 수 있어서다. 함정은 실무에서 자주 틀리는 비직관적 지점들이고, **이게 바로 공식 스킬이 존재하는
이유이기도 하다.**

테스트는 의존성이 0이다 — `tests/xlsx.js`가 `zlib`만으로 zip을 풀고 XML을 직접 파싱한다.
스타터 `package.json`에도 의존성이 없어서 **JS로 갈지 Python으로 갈지 힌트가 없다.**

## 시트 레이아웃

```
[상세]                                   [요약]
 1행  A1:F1 병합 = "2026년 2분기 매출 상세"   1행  카테고리 / 수량 합계 / 매출 합계
 2행  날짜 카테고리 상품명 수량 단가 금액      2~6행  카테고리 5개 (매출 합계 내림차순)
 3행~ 데이터 120행                          틀 고정: 1행
 틀 고정: 2행
```

## 단계별 요구와 함정

### 1단계 — 상세 시트 (워밍업)

- 시트 이름 정확히 `상세`. **1행은 비워둔다**(4단계 제목 자리 — 나중에 행이 밀리면 앞 테스트가 깨지므로 처음부터 비워두게 시켰다).
- 날짜는 **텍스트**로. Date 객체로 넣으면 엑셀 시리얼 숫자가 되어 탈락(`datetype` 함정).
- 수량/단가/금액은 **숫자**. 금액 = 수량 × 단가(csv에 없는 계산 컬럼).

### 2단계 — **이 문제의 핵심 함정**

요약 시트 합계를 **살아있는 수식 + 계산된 값** 둘 다로 만들어야 한다. 채팅에는 구현 얘기를 안 하고
업무 언어로만 적었다:

> "저희 팀은 엑셀을 안 쓰고 사내 문서 뷰어로 열어봐요. **뷰어에서 열었을 때 합계가 빈칸으로 보이면
> 안 됩니다.** 수식은 수식대로 살아있으면서 값도 같이 보여야 해요."

구현으로 번역하면 셀에 `<f>`(수식)와 `<v>`(캐시값)가 **둘 다** 있어야 한다. 도구마다 방식이 완전히 다르다:

| 도구 | 방법 |
|---|---|
| exceljs | `cell.value = { formula: "...", result: 계산값 }` |
| **openpyxl** | 캐시값을 못 쓴다 → **LibreOffice로 재계산 필수** |
| xlsxwriter | `write_formula(row, col, formula, fmt, value)` — `value` 인자가 캐시값 |
| SheetJS | `{ t:'n', f:'...', v: 계산값 }` |

**공식 `xlsx` SKILL.md가 정확히 이 둘을 맨 앞에서 경고한다** — "Use formulas, never hardcoded results"와
"Recalculate (mandatory whenever the file contains formulas)". 스킬을 쓴 쪽은 함정을 밟기 전에 알고
시작하고, 안 쓴 쪽은 "실행 → 빈칸 → 수정" 루프를 돈다. **그 루프가 곧 턴이고 비용이다.**

- 수식은 `상세` 시트를 참조해야 한다(테스트가 수식 문자열에 `상세`가 있는지 본다).
- 정렬은 **매출 합계 내림차순**. 수량 순서와 다르므로 실제 판별력이 있다.

### 3단계 — 표시 형식

| 대상 | 형식 | 함정 |
|---|---|---|
| 상세 `단가`/`금액`, 요약 `매출 합계` | `₩#,##0` | 값은 **계속 숫자**여야 한다. `"₩1,290,000"` 문자열로 넣으면 탈락(`strmoney` — 1단계 숫자 타입 검사까지 소급해서 깨진다) |
| 상세 `수량`, 요약 `수량 합계` | `#,##0` | 돈이 아니므로 통화 아님 |
| 상세 `상품명` 열 너비 | ≥ 20 | 기본 너비는 8 남짓이라 안 넓히면 탈락 |

> 열 너비를 정밀 비교하지 않고 `>= 20` 하한선으로 잡은 이유: **LibreOffice 라운드트립이 너비를
> 바꾼다**(지정 36 → 저장 30.05, 글꼴 환산 차이). 정밀 비교하면 재계산 경로가 억울하게 떨어진다.

### 4단계 — 병합 + **틀 고정 좌표 함정**

- 상세 1행 `A1:F1` 병합, 값은 `2026년 2분기 매출 상세`.
- **틀 고정 값이 시트마다 다르다** — 상세는 `ySplit=2`(제목+머리글), 요약은 `ySplit=1`(머리글만).
  상세 좌표를 요약에 복붙하면 여기서 잡힌다.
  - openpyxl은 `freeze_panes`에 **첫 번째 안 얼린 셀**을 준다(`"A3"` / `"A2"`), exceljs는 **개수**를
    준다(`ySplit: 2` / `1`) — API 규칙 자체가 반대라 헷갈리기 쉽다.

> **판별력 없는 항목 하나**: "병합 범위의 마스터가 아닌 칸에 값 쓰기" 함정은 파일 수준에서 검출이
> 안 된다 — exceljs는 병합 시 나머지 칸을 지우고 openpyxl은 `MergedCell.value`가 읽기 전용이라
> 예외를 낸다. 올바른 xlsx에는 그 상태가 존재할 수 없다. assert는 스펙 서술로 남겨뒀지만 실질
> 판별은 "병합이 있는가"와 "틀 고정 좌표"다.

## 환경 메모

이 컴퓨터에서 세 경로 전부 완주 가능한 것을 확인했다(가짜 홈 격리 안에서도 동일):

- `git clone anthropics/skills` ✓ · `npm install` ✓ · `python -c "import openpyxl, pandas"` ✓ · LibreOffice 재계산 ✓

**단, 스킬이 제공하는 `scripts/recalc.py`는 그대로는 실패한다** — LibreOffice는 설치돼 있지만
`soffice`가 PATH에 없어서 `soffice not found on PATH`로 죽는다. `soffice.exe`를 직접 부르면 되지만
**스킬 경로가 이 우회에 몇 턴을 더 쓸 수 있다.** 문제 설계가 아니라 이 머신의 환경 문제다.

## 채점

- **테스트**: 히든 20개(4단계 전부).
- **rubric 4개** — 전부 테스트가 **못 재는** 것만: 입력이 바뀌어도 재실행 가능한가(하드코딩 의존),
  생성 과정이 실행 가능한 형태로 남았는가, 구조·가독성, 예외 대비.
- **시간**: 10분 초과부터 감점, 15분 실격.

## 실사용 관측 (2026-08-11, 각 조건 n=1)

| | raw 토큰 | 가중 토큰 | 출력 토큰 | LLM 점수 |
|---|---|---|---|---|
| 스킬 안 씀 | 2,875,767 | 1,780,018 | 28,405 | 4.00 / 5 |
| 스킬 씀 | 2,339,320 | **1,196,762 (−33%)** | 15,679 | 3.25 / 5 |

- **둘 다 히든 테스트 전부 통과했다.** 품질 차이는 실질적인 것 하나 — 스킬 쪽이 요약 카테고리 목록을
  `CATEGORY_ORDER`에 하드코딩해서, csv가 바뀌면 정렬이 깨진다(고정 csv를 쓰는 테스트는 못 잡는다).
- 스킬을 안 쓴 쪽은 XLSX writer와 ZIP 구현을 직접 손으로 짰다(출력 토큰이 2배인 이유).
- **n=1씩이라 결론이 아니라 관측치다.** 브리프가 요구한 헤드리스 A/B는 아직 안 돌렸다.

> 이 두 run이 채점 파이프라인의 버그 3개(바이너리 덤프 / 큰 파일이 예산 독차지 / 채점자가 확정된
> 사실을 뒤집음)를 드러냈고, 그걸 고친 뒤의 값이 위 표다. 경위는 [evaluation.md](../evaluation.md).
