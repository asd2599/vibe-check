# game-tactics-staged 공략집

## 한눈에

| | |
|---|---|
| **측정 대상** | 앞 단계 규칙이 뒤 단계 작업에서 깨지는가 — 문서화(CLAUDE.md/docs)의 효과 |
| 난이도 / 분류 | hard / web-game |
| 산출물 | `game.js`(순수 함수, 테스트 대상) + `index.html`(rubric 대상) |

스타터에 의존성 없는 정적 서버(`server.js`, `npm start`)가 들어 있다 — `file://`의 ESM/CORS 문제를 피하려고.

## 설계 핵심 — 문서가 이기는 지점

문서가 이기는 건 "규칙을 어디에 적어뒀나"가 아니라 **누적된 불변 규칙이 뒤 단계 작업에서 깨지는가**다.
그래서 규칙을 **채팅으로만** 주고, 뒤 단계 기능이 앞 단계 규칙 **위에 얹히게** 만들었다:

- **4단계 궁극기 데미지는 `1단계 공식 → 2단계 지형 보정(대상별로 각각) → ×1.5 버림`을 전부 다시 탄다.**
- **3단계 독은 그 규칙들의 예외다** — 지형 무관 / 게이지 안 채움 / hp 1 하한.
- 턴 시작 처리 순서까지 고정: **독 먼저, 그 다음 게이지 확인.**

하나만 빠뜨리면 게이트가 앞 단계 테스트부터 되살려 실패시키고, **그 재시도 루프가 곧 토큰 비용**이다.

> **앞 단계 테스트의 불변성이 이 설계의 전제다.** 뒤 단계 기능이 앞 시나리오 결과를 바꿔버리면 앞
> 테스트가 저절로 깨져 게이트가 신호를 잃는다. 그래서 생성기가 **모든 시나리오를 자기 단계 레벨과
> 4레벨에서 각각 돌려 결과 동일성을 검증한 뒤에만** 테스트를 emit한다. (처음엔 피격당 게이지 +20이라
> 1단계 시나리오에서 궁극기가 터져 검증 실패 → +10으로 낮춰 해결.)

## `game.js` 계약

```js
createBattle(scenario)          // 초기 상태
turnOrder(state)                // 이번 라운드 행동 순서 (살아있는 유닛 id 배열)
legalMoves(state, unitId)       // [{x, y}, ...]
attackTargets(state, unitId)    // 대상 id 배열
applyAction(state, action)      // 새 상태 (원본 불변!)
```

```js
state = { width, height, terrain, units, order, current, round, winner }
action = {type:"move", unitId, x, y} | {type:"attack", unitId, targetId} | {type:"end", unitId}
```

- `terrain[y][x]` = `"plain"` / `"wall"` (2단계에서 `"forest"` / `"water"` 추가)
- `units`에는 **살아있는 유닛만** 남는다
- 유닛 필드: `id, team, x, y, hp, maxHp, atk, def, spd, move, range` + `hasMoved`, `hasAttacked`
  (`maxHp`가 시나리오에 없으면 `hp`로)
- 렌더링(DOM) 코드가 `game.js`에 섞이면 안 된다 — rubric 항목이다

## 1단계 규칙 (전부 비관습)

| # | 규칙 | 관습과 다른 점 |
|---|---|---|
| ① | 데미지 = `floor(atk × atk ÷ (atk + def))`, 최소 1 | **빼기 공식(atk − def)이 아니다** |
| ② | 턴 순서 = `spd` 내림차순 → 동점이면 **적군(enemy) 먼저** → 그래도 동점이면 `id` 사전순 오름차순 | 보통 아군 우선 |
| ③ | 이동은 **상하좌우 4방향만**. 벽은 물론 **다른 유닛이 서 있는 칸은 아군이라도 통과 불가.** 비용 합이 `move` 이하 | 보통 아군은 통과 가능 |
| ④ | 공격 사거리 = **맨해튼 거리** ≤ `range`. **시야 판정 없음**(벽/유닛이 사이에 있어도 무관) | 보통 체비셰프 거리 |
| ⑤ | 한 턴에 이동 1 + 공격 1인데 **순서 고정** — 이동 후 공격은 되지만 **공격하면 그 턴엔 못 움직인다** | |
| ⑥ | `hp` 0 이하면 즉시 `units`에서 제거, 한쪽 팀 전멸 시 `winner` | |
| ⑦ | 규칙 위반 액션은 `Error` 던지기 | |
| ⑧ | `legalMoves`는 현재 칸 제외 + `y`→`x` 오름차순, `attackTargets`는 `id` 오름차순 | |

순서는 라운드 시작에 확정하고 그 라운드 동안 유지하되, 중간에 죽은 유닛은 건너뛴다.

## 2단계 — 지형 (**적용 순서가 결과를 바꾼다**)

이동 비용: 평지 1, 숲 2, 물 3 (벽은 통과 불가).

| 보정 | 조건 | 계산 |
|---|---|---|
| 숲 | **방어하는 쪽**이 숲에 서 있음 | `floor(데미지 × 0.75)`, 최소 1 |
| 물 | **공격하는 쪽**이 물에 서 있음 | `데미지 − 1`, 최소 1 |

- 숲은 **방어자** 지형만, 물은 **공격자** 지형만 본다. 반대는 아무 영향 없다.
- **적용 순서: `1단계 기본 공식` → `숲 보정` → `물 보정`.** 순서가 바뀌면 값이 달라지는 케이스가
  테스트에 들어 있다.

## 3단계 — 독 (**앞 규칙들의 예외**)

`venom: true`인 유닛이 공격해서 데미지가 들어가면 대상이 중독된다.

- `poisonTurns`를 **3으로 설정**(누적이 아니라 덮어쓰기).
- 독 피해는 **그 유닛의 턴이 시작될 때** `floor(maxHp × 0.1)`, 최소 1. **현재 hp가 아니라 maxHp 기준.**
- **지형 보정을 적용하지 않는다** — 숲에 서 있어도 그대로 다 들어온다.
- **독으로는 죽지 않는다** — hp가 1 밑으로 내려가면 1에서 멈춘다. `units`에서 사라지면 안 된다.
- `poisonTurns`는 **그 유닛의 턴이 끝날 때** 1 감소 → 3턴이면 총 3번 피해.

## 4단계 — 궁극기 게이지

- 모든 유닛이 `gauge`(0~100, 기본 0). **공격을 받으면 +10**(최대 100). **때린 쪽은 안 오른다.**
- **독 피해로는 게이지가 안 오른다.** 직접 맞은 것만.
- 발동은 자동: **자기 턴 시작 시 `gauge`가 100이면** 그 턴은 궁극기.
  - 대상 = 자기 위치에서 **맨해튼 거리 2 이내의 적 전원**.
  - **대상이 하나도 없으면 발동하지 않고 게이지를 그대로 유지**한다. 이 경우 평소처럼 이동/공격 가능.
  - 데미지 = **1단계 공식 → 2단계 지형 보정(숲/물) → 마지막에 `× 1.5` 버림**, 최소 1.
    **지형 보정은 대상마다 각각 계산**한다(서 있는 칸이 다르므로).
  - 궁극기에 맞은 쪽도 게이지 **+10**.
  - 발동 후 `gauge = 0`, **그 턴엔 이동도 공격도 못 한다**(`end`만 가능).
- **턴 시작 처리 순서: 독 피해 먼저, 그 다음 게이지 확인.**

## 검증된 판별력 (실측)

| 시나리오 | 결과 |
|---|---|
| 정석 구현 | 4단계 게이트 전부 + 히든 통과 |
| 관습적 구현(빼기 데미지 · 아군 우선 · 체비셰프 사거리) | **1단계 탈락** |
| 조기 완료(일부 단계만) | 히든 테스트가 차단 |
| 4단계에서 지형 보정을 건너뛴 회귀 | `stage4` 게이트가 정확히 검출 |

히든 테스트 픽스처 21개(단계별 시나리오 + `h1~h4` 히든 시나리오).

## 미검증 — 정직하게 남긴 것

- **"문서를 쓴 참가자가 실제로 토큰을 덜 쓰는가"는 측정하지 않았다.** 검증한 건 게이트 판별력뿐이다.
- 앞선 A/B에서 확인했듯 **한 세션을 유지하면 규칙이 컨텍스트에 그대로 남아 문서가 개입할 여지가 없다.**
  문서가 이기려면 컨텍스트가 실제로 손실돼야 한다(compact 발생, `/clear`, 세션 재시작). 이 문제는
  분량이 커서 compact가 걸릴 가능성이 높다는 데 기대고 있지만, 라이브 세션 의존이라 확인 못 했다.
- **예산·시간도 실측이 아니다.** $3.0은 턴당 $0.0423 기준 어림이고, 30/50분도 완료 데이터가
  사실상 없다(유일한 완료가 0.8분). **첫 제대로 된 실사용 run 이후 반드시 재조정할 것.**

## 채점

- **테스트**: `game.js` 로직만 `node --test`로 결정론적 채점.
- **rubric 6개**: 비관습 규칙 정확 반영, **뒤 단계가 앞 규칙을 안 깨뜨림(특히 궁극기가 지형 보정을
  대상별로 다시 타는지)**, 웹 화면이 실제로 게임으로 동작, 시각적 완성도, `game.js`가 렌더링과 분리된
  순수 함수로 유지, 가독성.
- **시간**: 30분 초과부터 감점, 50분 실격.

## 진행 전략 (효율 관점)

- 화면 쪽은 명시되지 않은 결정(레이아웃/피드백/지형 표현)이 많아 **시각 반복 루프**가 자연스럽게 생긴다 —
  여기가 사전 계획 문서의 값이 나오는 두 번째 지점이다.
- 데미지 계산을 **단일 함수로 모아두면** 4단계 궁극기가 그 함수를 재사용하는 것만으로 끝난다.
  단계마다 계산식을 복사하면 궁극기에서 지형 보정을 빠뜨리는 회귀가 거의 확정적으로 난다.
